# APS — моделирование системы массового обслуживания

Событийная модель СМО: источники генерируют заявки, свободные приборы их обслуживают, а заявки, пришедшие при занятых приборах, ждут в буфере.

## Модель

- **Источники** создают заявки через фиксированные интервалы.
- **Приборы** выбираются по кругу. Время обслуживания распределено экспоненциально со средним `processing_time`.
- **Буфер** ограниченного размера. Приоритет заявки определяется номером источника: чем меньше номер, тем выше приоритет.
  - *Отказ:* если буфер полон, из него вытесняется самая новая заявка источника с наименьшим приоритетом.
  - *Выбор на обслуживание:* пакетный. Пока в буфере есть заявки текущего приоритетного источника, обслуживаются они.

## Запуск

Запускать из корня проекта, потому что конфиг читается по относительному пути:

```bash
cargo run
```

Пошаговый режим: Enter переходит к следующему событию, `end` досчитывает до конца без вывода.

Только итоговые результаты:

```bash
echo end | cargo run --release
```

## Настройка

Параметры задаются в `src/config/config.txt` (формат TOML):

```toml
sources = [4.1, 8.1, 5.1]   # интервалы генерации заявок, по одному на источник
num_devices = 11            # число приборов
buffer_size = 4             # размер буфера
processing_time = 4.5       # среднее время обслуживания
simulation_time = 1000      # длительность моделирования
```

## Результаты

- **В консоли:**
  - по источникам — число заявок и процент отказов;
  - по приборам — число обслуженных заявок и время простоя;
  - по буферу — время в заполненном состоянии.
- **`diagram.puml`** — временная диаграмма состояний источников, приборов и буфера для [PlantUML](https://plantuml.com).

## Структура

| Модуль | Назначение |
|---|---|
| `qs` | основной цикл моделирования, статистика, UML-диаграмма |
| `special_event_api` | календарь особых событий |
| `source` | источники заявок |
| `buffer` | буфер и дисциплины постановки и выбора заявок |
| `device_api` | приборы |
| `request` | заявка |
| `config` | загрузка параметров |
